# Performance & Observability Standup Brief (2025-08-29)

## Sprint Goal
Reduce Largest Contentful Paint (LCP) below **2.5 s** on the landing route while preserving perceived polish and establishing a sustainable performance & observability foundation.

## What’s Done
- **Instrumentation**: Web Vitals hook with subscriber fan‑out + optional in‑page overlay; automated Lighthouse script with detached preview, readiness probe, retries.
- **CLS Mitigation**: Fixed header height, aspect‑ratio placeholders, transform‑only animations, reserved hero space.
- **Critical Path Work**:
  - Inlined minimal critical CSS (header + hero typography/layout).
  - Local Inter variable font preload (font-display: swap).
  - Skeleton header + static hero fallback.
- **LCP Element Analysis**: Progression observed — `p.hero-sub` → transient error `<pre>` (runtime overlay) → stabilized at `h1.giant-text`.
- **Runtime Error Removed**: Disabled premature framer-motion enhancement that created an error `<pre>` capturing LCP.
- **Deferrals Implemented**:
  - Removed framer-motion from initial render (static hero + layout; motion wrappers stripped).
  - Deferred global stylesheet via requestIdleCallback + `preload` (partial: blocking stylesheet still injected by Vite; needs final removal).
- **Bundle Analysis**: Generated `dist/stats.html` (Rollup visualizer) for size & split decisions.

## Current Metrics (Latest Lighthouse)
- First Contentful Paint (FCP): **2.3 s**
- Largest Contentful Paint (LCP): **3.0 s** (improved from ~3.63 s baseline; target still unmet)
- LCP Element: `h1.giant-text`

## Key Findings
- LCP dominated by **Render Delay** (post-TTFB) – blocking CSS + main bundle CPU time.
- Duplicate inclusion of main stylesheet (both deferred preload + standard blocking `<link rel="stylesheet">`) negates intended benefit.
- Framer Motion no longer on the critical path; remaining cost from base bundle + large unified CSS (~142 KB built).
- Error overlay risk mitigated (removed source of `<pre>` element).

## Risks / Watch Items
- Reintroducing motion globally without guarded dynamic import could regress LCP.
- Current deferral pattern incomplete until the blocking CSS link is suppressed.
- No performance budget enforcement yet; risk of silent asset growth.

## Next Actions (Proposed)
1. **Eliminate Blocking CSS Link**: Transform `index.html` post-build (or Vite HTML plugin) to keep only `preload` + onload swap.
2. **Refine Critical CSS**: Trim inline block to only hero/header essentials; push other rules to deferred sheet.
3. **Code Split Non-Critical Shell**: Lazy-load LogoIntro, CustomCursor, and heavy panel/rotator logic after interaction or viewport.
4. **Font Optimization**: Subset Inter (Latin basic); add `font-size-adjust`; evaluate optional second stage swap for full set.
5. **Hero Ownership of LCP**: Ensure no late style mutations (explicit line-height, letter-spacing, fallback font metrics alignment).
6. **Performance Budgets**: Add CI check (fail build if main JS > 180 KB gzip, deferred CSS > threshold, or LCP simulated > target).
7. **Priority Hints**: Assign `fetchpriority="high"` to primary font + root JS; demote non-critical preloads.
8. **Progressive Animations**: Re-introduce hero letter animation only after `LCP` event or idle (post measurement strategy).
